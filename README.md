# Android APK Emulator على GitHub

ارفع أي APK واحصل على فيديو ولقطات وتقرير crashes من غير موبايل ولا كمبيوتر قوي.
كل الشغل بيتم على سيرفرات GitHub Actions (مجاني للمشاريع العامة).

## محتويات المشروع
```
.github/workflows/android-emulator.yml   الـ workflow الأساسي (تلقائي)
.github/workflows/interactive.yml        جلسة تفاعلية من المتصفح (تجريبي)
scripts/get_apk.sh                       تجهيز الـ APK (رابط / فولدر / xapk / apks)
scripts/run.sh                           التشغيل والتصوير والتحليل داخل المحاكي
scripts/interactive.sh                   نفق noVNC للجلسة التفاعلية
flows/example.yaml                       سيناريو Maestro عام
flows/telegram_test_dc.yaml              قالب لاختبار عميل تليجرام (TDLib)
apks/                                    حط الـ APK هنا
```

## التركيب (مرة واحدة)
1. اعمل repo جديد على GitHub (**public** للمجاني الكامل).
2. ارفع كل محتويات المجلد (بما فيها المجلد المخفي `.github`).
3. Settings ← Pages ← Source: **GitHub Actions**.

## التشغيل
**تلقائي:** ارفع `.apk` أو `.xapk` أو `.apks` داخل `apks/`.
**يدوي:** Actions ← Android APK Emulator ← Run workflow:
- `apk_url`: رابط مباشر بدل الرفع.
- `api_levels`: أكتر من إصدار، مثال `29,34`.
- `fail_on_crash`: يفشّل الـ workflow لو حصل crash (للاستخدام كاختبار آلي).
- `skip_monkey`: يعطّل الضغط العشوائي (مهم مع الحسابات الحقيقية).
- `publish_pages`: عطّله لو النتائج فيها بيانات خاصة.

النتيجة: `https://USERNAME.github.io/REPO/` (فيديو + لقطات + حالة + logcat).

## سيناريوهات Maestro
حط ملفات `.yaml` في `flows/`، والتطبيق بيتحدد تلقائياً عبر `${APP_ID}`.
سمّي اللقطات `flow_xxx` عشان تظهر في الصفحة.
الأسرار: أي Secret اسمه `FLOW_PHONE` أو `FLOW_CODE` أو `FLOW_PASSWORD` بيتبعت للسيناريو
(`${FLOW_PHONE}`) وبيتمسح من لوج الصفحة (مش من الفيديو واللقطات).

## اختبار عميل تليجرام (TDLib)
كود الدخول بيوصل لحسابك الحقيقي، فالـ workflow مش هيعرفه وقت التشغيل. الحلول:

1. **حساب Test DC (الأفضل):**
   - التطبيق لازم يتصل بسيرفرات الاختبار (`use_test_dc = true` في TDLib).
   - الرقم: `99966XYYYY` (X = رقم الـ DC من 1 لـ 3). على أندرويد: كود الدولة `+999` والباقي `66XYYYY`.
   - الكود: رقم الـ DC متكرر 5 مرات (مثلاً `22222`)، ولو مشتغلش جرّب 6 مرات.
   - ضيف الأسرار `FLOW_PHONE=6621111` و`FLOW_CODE=22222` (و`FLOW_PASSWORD` لو في 2FA).
   - عدّل `flows/telegram_test_dc.yaml` حسب شاشات تطبيقك، وشغّل بـ `skip_monkey` مفعّل.
   - متحطش بيانات حقيقية في حسابات الاختبار، لأن أي حد يقدر يدخلها.
2. **جلسة تفاعلية:** شغّل `interactive.yml` واكتب الكود بإيدك (تجريبي).
3. **حساب حقيقي في الـ CI:** غير مستحسن (ممكن تليجرام يقيّد الحساب بسبب IPs السيرفرات).
   لو اضطريت: repo **private** + `publish_pages` معطّل، لأن الفيديو بيظهر الكود والمحادثات.

ملحوظة: واجهة تليجرام مرسومة مخصوص، فلو Maestro مالقاش النصوص استخدم الإحداثيات:
`tapOn: { point: "50%,80%" }`.

## الجلسة التفاعلية (تجريبية)
1. Settings ← Secrets ← Actions ← أضف `VNC_PASSWORD` (**8 حروف بالظبط**).
2. Actions ← Interactive Emulator ← Run workflow.
3. افتح الرابط من Summary الـ run وادخل الباسورد. تنتهي بعد المدة المحددة (أقصاها 60 دقيقة).
- بطيئة لأن المحاكي بدون كارت شاشة، وغير مختبرة، وفيها منطقة رمادية في شروط GitHub (نفق للخارج). استخدمها باعتدال.

## حدود وتحذيرات
- المشروع **غير مختبر على GitHub فعلياً**؛ الصياغة اتفحصت بس. متوقع تعديلات بسيطة في أول تشغيل.
- الـ repo العام = الـ APK والنتايج ظاهرة للجميع.
- `.aab` مش مدعوم. الملفات أكبر من 100MB استخدم لها رابط مباشر.
- التطبيقات ARM فقط هتشتغل بالترجمة (بطيء). تطبيقات Google Play Services المعقدة ممكن متشتغلش.
- لو طلع خطأ، ابعت رسالة الخطأ من تبويب Actions.
